# 对话审计：待确认事项

这些事项已发现或核对，但本轮不擅自改变协议与产品语义。明确缺陷修复和验收结果另见对话审计报告。没有自动作答、自动重发、删除会话或修改用户配置。

## 1. 辅助对话创建成功、首问失败后的重启恢复

**已知未修复缺口。** 创建成功会保留有编号的真实辅助会话。若首次提问在写入本会话边界前失败，重启会丢失临时输入页与新会话的关联；该会话仍可从列表打开。随后普通发送没有建立首次上下文边界，严格的历史隔离可能隐藏持久化消息。

这与本轮已修的“正常首问交接和隐藏首问”不同，不能算已修复。不能通过删除或隐藏会话、自动重发、放宽所有隐藏规则来规避。

### 选择

- **受限保守恢复**：仅在父子完整记录足以证明来源时恢复；缺失、重写或歧义时明确报错并保留草稿。覆盖有限，旧记录存在无法证明的情况。
- **推荐：持久的首次初始化身份与恢复协议**：在创建返回前持久记录继承边界，并以权威写入记录区分“尚未提问”和“已提问但响应丢失”。需要处理创建响应丢失、旧会话迁移、嵌套辅助会话和父历史重写。它涉及生命周期契约与迁移，不作为小型显示修复偷偷加入。

显示编号和时间都不是可靠身份。现有会话文件头只有父会话身份，没有继承截止身份；单纯新增浏览器标记既不能修复旧会话，也覆盖不了创建响应之前的崩溃。

**验收要求**：创建前后崩溃、首问拒绝、已落盘但响应丢失、重复点击、重启、嵌套会话、父会话重命名或删除、旧数据迁移、图片和引用，均不得自动重复发送或丢草稿。

**证据**：`src/features/sidechat/sideChatActions.ts`、`viewStore.ts`；`src/features/chat/sideChatView.ts`；`src/features/sessions/grouping.ts`；`src-tauri/src/rpc/sidechat.rs`；`src-tauri/src/catalog/{scan,transcript}.rs`。上游核查版本 `96e4d8e`：创建复制原记录身份，但未记录继承截止身份。完整取证保留在本轮审计附件。

## 2. 启动扩展在会话就绪前要求用户回答

**已知未修复缺口。** 自定义扩展可在启动阶段等待用户选择；上游会先接受弹窗回答，但暂缓普通查询。宿主目前等待查询成功才绑定会话并排出缓冲事件，导致启动弹窗无法到达可回答界面。

### 选择

- 维持现状并明确启动失败，用户自行调整该扩展；改动小，但启动交互不可用。
- **推荐：独立启动身份和弹窗路由**。每次启动有隔离身份；回答、取消、断连均定位该次启动，成功后再绑定正式会话，失败清理。桌面和手机需要一致的入口与错误恢复。
- 不采用自动批准、自动取消或静默禁用扩展：这些做法会替用户决定。

新握手若支持二次协商，协商与状态查询各可等待约 120 秒；旧握手通常只等待状态查询。此前还可能有最多 30 秒的就绪等待。这不是包含系统调度和进程准备的总启动时间保证。

**验收要求**：多次并发启动不串回答；启动取消、超时、断连不留下半活会话；只接受用户明确选择；成功绑定后不重放旧弹窗。临时规避仅限用户主动调整有问题扩展的启动交互，不修改用户配置。

**证据**：`src-tauri/src/rpc/process.rs`；上游 `96e4d8e` 的启动握手和扩展初始化顺序。

## 3. 新输入与暂存消息的顺序和回合

当前行为是新输入在前，再合并暂存内容为一次请求。需要决定：

1. 保持现状；
2. 按暂存先后顺序合并；
3. 逐条作为独立回合发送。

这会改变模型看到的顺序、上下文及费用。本轮只修发送期间编辑丢失、异步确认错删和附件未发即消费，保留现有顺序与合并行为。

## 4. 从队列移除后的去向

上游队列移除会恢复草稿，本地暂存气泡移除则直接丢弃。需要决定统一恢复草稿，还是用明确的操作名称区分“撤回到草稿”和“删除”。

本轮保留现有数据去向，仅修稳定目标身份和发送快照消费，不借一致性调整改变行为。
