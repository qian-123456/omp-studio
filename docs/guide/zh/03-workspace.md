## 认识右侧面板多标签体系

右侧面板集合了代码研发与项目调试的核心工具，按快捷键 `⌘J` 可随时展开或收起。

点击标签栏末尾的 `+`（打开新标签页）可以在右侧自由添加并切换以下工具：

| 标签页 | 核心用途与能力 |
| --- | --- |
| **文件** | 树状浏览当前项目的工作区文件，支持实时过滤与快速定位 |
| **Git** | 未提交改动审查、文件 Diff、工作树并行管理、分支切换与版本历史 |
| **终端** | 内置持久化命令行，支持开启多个终端标签，并可将终端折叠为后台服务 |
| **文件预览** | 点击对话中的文件路径或文件面板中的代码时激活，支持只读预览与即时编辑 |
| **辅助对话** | 无干扰轻量级侧聊，随时向智能体提出独立问题 |
| **本地服务** | 扫描当前本机端口占用，识别开发服务器，并一键终止残留进程 |
| **Token 用量** | 分析上下文开销构成，下钻检查工具调用浪费，进行会话深度体检 |

> [!NOTE]
> 处于「规划模式」时，系统会自动在右侧打开专属的 **计划** 标签页，实时展示智能体拟定的方案实施步骤与勾选进度。

## 文件面板与文件搜索

打开右侧的 **文件** 即可查看当前工作区的文件目录树。

### 目录与文件操作
- **快速过滤（`⌘F`）**：在顶部搜索框输入文件名，即时过滤展示匹配文件；
- **访达联动**：点击工具栏的访达图标，在系统文件管理器中直接定位当前项目根目录；
- **右键上下文菜单**：
  - **在访达中显示**：在 macOS 访达中高亮当前文件；
  - **复制相对路径 / 完整路径**：精准拷贝路径供提示词使用；
  - **刷新目录**：重新读取磁盘变动。

单击任何文件，将在中央主区域打开 **文档视图**。

## 预览与分栏编辑

omp-workspace 提供两种轻巧舒适的代码与文档查看方式：

1. **中央文档视图**：占据中央区域，提供大视野的沉浸式阅读与修改；
2. **右侧文件预览标签**：在对话中点击智能体提到的文件路径时就地激活。

### 三种视图布局自由切换
在中央文档视图顶部，可根据需要随时切换：
- **预览模式**：富文本渲染 Markdown，格式精美且链接均可点击；
- **分栏模式（Split）**：左侧展示源码编辑器（CodeMirror 支持智能高亮），右侧实时同步渲染预览；
- **编辑模式**：纯代码编辑视图，按 `⌘S` 快速保存写入磁盘。

### 外部修改智能感知
当代码在 VS Code 等外部编辑器被修改并切回 omp-workspace 时，未修改的干净缓冲区会自动静默刷新；若本地有尚未保存的编辑内容，系统会弹出冲突保护提示，让你自由选择「重新加载磁盘内容」或「保留当前修改」。

### 划选内容一键批注
在预览或编辑器中划选代码行，底部会浮出 **添加批注** 工具条。输入改进意见并按 `⌘Enter`，该代码段与你的诉求将立即装配成精准的上下文送入输入框，无需手动复制粘贴文件路径与行号。

## Git 改动审查与智能存档

在右侧打开 **Git** 标签页，面板自动绑定当前所选会话的工作目录。

### 改动审查与 Diff 窗口
在 **改动** 子标签下列出了所有未提交的文件及其变更状态（修改、新增、删除、重命名）：
- **单文件操作**：点击文件行可 **复制相对路径**、**派发给智能体审查** 或 **撤销此文件改动**；
- **全屏 Diff 审查**：点击 **全部 Diff**，打开多文件差异审查面板。支持：
  - **单栏合并（Unified）** 与 **双栏对比（Split）** 自由切换；
  - 语法高亮与行号对齐；
  - **逐行行间批注**：选中任意变动代码行，点击行号旁的批注按钮，直接针对具体代码行向智能体发出修正意见！

### AI 生成提交说明与本地存档
点击 **存档：提交全部 N 个文件**：
- 系统会自动调用轻量模型分析当前代码 Diff，一秒生成符合语义化规范（Conventional Commits）的中文提交信息；
- 也可以手动编辑提交说明后按 `⌘Enter` 完成提交；
- 存档完全在本地 Git 仓库安全执行，绝不会在你未经确认的情况下擅自推送到远程仓库。

## Git Worktree 独立工作树并行实战

在传统的单工作区开发中，如果让智能体同时处理两个任务，不同分支的代码会发生交叉污染甚至文件覆盖。omp-workspace 原生基于 **Git Worktree（工作树）** 彻底终结了这一痛点。

### 什么是工作树？
工作树是 Git 提供的高级能力：它允许你在同一个本地仓库中，将多个不同分支同时检出到不同的独立磁盘文件夹中。每个工作树拥有独立的编译产物、依赖和未提交修改，物理级隔离！

### 工作树操作全景
在 Git 面板切换至 **工作树** 视图：
1. **新建并行工作树**：点击顶部的 **新建并行工作树**（或从已有分支派生），指定分支名后系统自动在 `.worktrees/` 目录下完成就绪；创建时务必带上清晰的任务或特性区分标识（如 `bug-fix-auth`、`feat-tab-sync`），避免使用 `test`、`temp` 等模糊无区分名称；
2. **多会话并行研发**：在不同的工作树中分别启动智能体，一个修 Bug，一个开发新特性，两者互不影响；
3. **主干同步与变基**：
   - **从 main 同步**：自动检测主干最新变动并合入当前分支，前置执行冲突预检；
   - **AI 辅助解决冲突**：预检发现冲突时，可一键开启专门的解冲突会话，由智能体自动读取冲突标记并完成修复；
4. **主干交付模式**：
   在 **设置 ▸ 通用 ▸ Git ▸ 主干交付模式** 中可选：
   - **发起 Pull Request（推荐）**：自动将分支推送到远程仓库并在浏览器中拉起 GitHub / GitLab 的 PR 页面；
   - **本地合并并直接推送**：将特性分支快速快进合入本地 main 分支并推送。
5. **闲置工作树智能回收**：当某个工作树关联的所有会话均已关闭或归档时，面板会浮现 **闲置工作树** 提示，点击 **一键回收** 即可安全清理磁盘空间。

## 时光机版本回溯与快照预览

在 Git 面板切至 **历史** 视图，按时间线查看提交记录。点击任意提交，可使用强大的时光机三部曲：

1. **看看（审查 Diff）**：查看该历史版本当时做了哪些具体变动；
2. **试试（时光机沙盒快照预览）**：
   - 想要验证 3 天前的一个历史版本，但又不想打乱当前正在写的代码？
   - 点击 **时光机快照预览**，系统会在隔离的临时目录（`.worktrees/tm-xxxx`）中启动一个只读的独立运行环境，并自动执行启动命令（如 `pnpm dev --port 5180`）；
   - 你可以在浏览器中一边体验旧版本的运行表现，一边继续在当前工作区编写代码！
3. **回到（版本安全穿梭）**：
   - **保留之后的修改（推荐）**：将 HEAD 软回退到该版本，其后的所有提交内容安全保留为工作区中的未提交改动；
   - **彻底回滚**：彻底丢弃之后的一切提交与未提交代码（高危操作，需输入确认）。

## 内置多标签终端

点击顶部工具栏的终端图标或按快捷键 `` ⌘` `` 即可在右侧唤出全功能终端。

- **多终端并发**：支持点击 `+` 开启最多 10 个独立 Shell 标签，每个标签以当前工作目录环境启动；
- **终端与对话深度联动**：
  - 在终端中划选任何错误堆栈或输出日志，直接点击 **引用** 即可附加为对话批注（快捷键 `⌘⇧A`）；
  - 支持一键 **发送到侧聊**，让辅助智能体协助分析终端报错；
- **折叠为后台常驻服务**：
  - 点击终端标签上的 **折叠为后台服务** 按钮，该进程将收拢进 **服务** 面板常驻运行，释放界面空间；
- **自动上下文承接**：在内置终端中直接输入 `omp` 启动命令行，将自动感知并接续当前图形界面的会话记录。
