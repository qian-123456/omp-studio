## 3. 终极设计规范速查表 (Final Design Specification)

经过 5 轮深度 Grilling 与真实代码对照，全部视觉与交互契约已 100% 达成一致：

1. **分支节点**：Option A 原生树节点。分支计数数字 `(22)` 默认隐藏，鼠标 Hover 时浮现；`+` 键默认半透明显性化；保留 2px 引导竖线。
2. **选中会话**：整行柔和浅底高亮 + 字重微加粗；标题左侧**绝不加竖线、绝不加圆点**，标题严格左对齐。
3. **相对时间**：去掉“前”字（`8分钟`、`1小时`、`昨天`），常驻右侧显示。
4. **操作菜单 (Time Swap)**：彻底拿掉方框背景与边框，纯净原生 `...`；鼠标悬停时平滑替换时间戳，零额外空间占用。
5. **分页控件**：1px 细线纯文字，去胶囊、去括号、以 `｜` 隔开展开与收起，极窄侧边栏自适应。
6. **会话状态**：
   - 运行中：Codex 风格单色 11px 细线旋转 Loader（无彩色），Hover 展开 `运行中`；
   - 待回复：常驻微型天蓝底文字胶囊 `[待回复]`（免悬停一眼看清卡点）；
   - 待验收：精致绿色微点 🟢，Hover 展开 `● 待验收`；
   - 报错：警告红色微点 🔴，Hover 展开 `● 出错`；
   - 空闲：无点无色，标题完全撑满。

## 3. 技术机制深度解析：“待验收” vs “待确认” 程序底层区别

根据 `src-tauri` 后端契约（`contracts.rs` / `notify/mod.rs` / `catalog/store.rs`）：

1. **`review`（待验收 - Turn End / 交付态）**：
   - **触发时机**：Agent 已经**跑完了当前轮次（Turn Completed）**，做好了代码修改、写好了测试或生成了结果。
   - **底层状态**：`SessionStatus::Review`，对应的待办分类为 `PendingKind::Review`。
   - **系统提示**：`"已完成，待验收"`。
   - **业务语义**：这是**积极成果交付**！Agent 任务告一段落，交还控制权等待人类 Review 成果。因此用**绿色（🟢）**代表成功交付，心理认知极其通顺。

2. **`awaiting_approval` / `awaiting_answer`（待确认/待批准/待回复 - Interactive Interrupt / 阻塞态）**：
   - **触发时机**：Agent **正在执行中（未完成）**，但由于触发了危险操作（如终端高危命令审批），或者 Agent 主动调用了 `ask` 工具向人类提问澄清需求。
   - **底层状态**：`SessionStatus::AwaitingApproval` 或 `SessionStatus::AwaitingAnswer`，对应的待办分类为 `PendingKind::Approval` 或 `PendingKind::Question`。
   - **系统提示**：`"等待审批"` / `"有问题等你回答"`。
   - **业务语义**：这是**中途阻塞挂起**！如果不及时确认或回答，Agent 就卡在这里无法往下推进。因此用**琥珀橙色（🟠）**代表警示与阻塞等待，提醒用户及时响应。
