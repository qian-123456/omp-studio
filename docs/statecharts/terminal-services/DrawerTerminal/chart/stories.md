## 1. 标签显示连接中，没有终端进程，面板已打开，界面里没有终端

Rule broken: 面板打开、标签可见并显示“连接中”时，必须真的有一次终端启动在进行或已完成。
Why: 点击重新连接只销毁了旧终端并把标签改回连接中，而创建终端的流程只在标签切换或面板挂载时才会再次运行.
In the model, 2 different steps lead into this bug: "点击重新连接" and "界面收到退出通知". The steps below are the shortest path that TLC found.

0. Start: 没有标签，没有终端进程
1. 打开终端面板. Now: 标签显示连接中，没有终端进程，面板已打开
2. 界面创建终端并请求启动. Now: 标签显示连接中，没有终端进程，面板已打开，启动请求未返回
3. 后端启动失败. Now: 标签显示启动失败，没有终端进程，面板已打开
4. 点击重新连接. Now: 标签显示连接中，没有终端进程，面板已打开，界面里没有终端

## 2. 标签显示运行中，终端进程在运行，面板已打开，第一段输出已丢失

Rule broken: shell 打印的第一段输出不应在到达界面前被丢弃。
Why: shell 的第一段输出在启动请求返回之前到达，而界面此时还不认识该终端，数据被直接丢弃.
In the model, 8 different steps lead into this bug: "界面收到退出通知", "启动请求返回", "关闭标签", "后端启动失败", "切走右侧面板", and 3 more. The steps below are the shortest path that TLC found.

0. Start: 没有标签，没有终端进程
1. 打开终端面板. Now: 标签显示连接中，没有终端进程，面板已打开
2. 界面创建终端并请求启动. Now: 标签显示连接中，没有终端进程，面板已打开，启动请求未返回
3. 后端成功启动 shell. Now: 标签显示连接中，终端进程在运行，面板已打开，启动请求未返回
4. Shell 打印第一段输出. Now: 标签显示连接中，终端进程在运行，面板已打开，启动请求未返回，第一段输出已丢失
5. 启动请求返回. Now: 标签显示运行中，终端进程在运行，面板已打开，第一段输出已丢失

## 3. 标签显示运行中，终端进程已结束，面板已打开

Rule broken: 标签显示“运行中”时，后端终端进程确实还活着。
Why: shell 在启动请求返回之前就退出了，退出通知因为界面还不认识该终端而被丢弃，标签随后被标成运行中.
In the model, 4 different steps lead into this bug: "启动请求返回", "切走右侧面板", "折叠成后台服务", and "面板重新挂载已有终端" (the state stays the same). The steps below are the shortest path that TLC found.

0. Start: 没有标签，没有终端进程
1. 打开终端面板. Now: 标签显示连接中，没有终端进程，面板已打开
2. 界面创建终端并请求启动. Now: 标签显示连接中，没有终端进程，面板已打开，启动请求未返回
3. 后端成功启动 shell. Now: 标签显示连接中，终端进程在运行，面板已打开，启动请求未返回
4. Shell 退出. Now: 标签显示连接中，终端进程已结束，面板已打开，启动请求未返回，退出通知在路上
5. 界面收到退出通知. Now: 标签显示连接中，终端进程已结束，面板已打开，启动请求未返回
6. 启动请求返回. Now: 标签显示运行中，终端进程已结束，面板已打开
