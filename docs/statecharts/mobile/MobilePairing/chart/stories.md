## 1. 链接预览已拿到令牌: 配对码已用，无事件流，未订阅通知，已推送0次

Rule broken: 规则：配对码只能被手机兑换，链接预览之类的访问不应拿到设备令牌。
Why: 打开配对链接这个无需登录的 GET 请求就会兑换配对码，任何访问者都能拿到令牌.
In the model, one step leads into this bug: "链接预览抢先打开配对链接". The steps below are the shortest path that TLC found.

0. Start: 无已配对设备: 无配对码，无事件流，未订阅通知，已推送0次
1. 电脑生成配对码. Now: 无已配对设备: 配对码有效，无事件流，未订阅通知，已推送0次
2. 链接预览抢先打开配对链接. Now: 链接预览已拿到令牌: 配对码已用，无事件流，未订阅通知，已推送0次

## 2. 手机已配对: 配对码已用，无事件流，已订阅通知，30秒内已通知，已推送1次

Rule broken: 规则：订阅了通知的手机，每次审批请求都应收到通知，不应被去重悄悄吞掉。
Why: 三十秒内的第二个审批请求被当作重复通知丢弃，订阅的手机收不到.
In the model, one step leads into this bug: "会话进入等待审批". The steps below are the shortest path that TLC found.

0. Start: 无已配对设备: 无配对码，无事件流，未订阅通知，已推送0次
1. 电脑生成配对码. Now: 无已配对设备: 配对码有效，无事件流，未订阅通知，已推送0次
2. 手机打开配对链接. Now: 手机已配对: 配对码已用，无事件流，未订阅通知，已推送0次
3. 手机开启通知. Now: 手机已配对: 配对码已用，无事件流，已订阅通知，已推送0次
4. 会话进入等待审批. Now: 手机已配对: 配对码已用，无事件流，已订阅通知，30秒内已通知，已推送1次
5. 会话进入等待审批. Now: 手机已配对: 配对码已用，无事件流，已订阅通知，30秒内已通知，已推送1次

## 3. 手机已配对: 配对码已用，事件流在线，已订阅通知，正在前台查看，30秒内已通知，已推送1次

Rule broken: 规则：手机正在前台查看会话且事件流在线时，不应再对它推送通知。
Why: 手机从不上报自己正在查看哪个会话，服务器无法跳过这次推送.
In the model, one step leads into this bug: "会话进入等待审批". The steps below are the shortest path that TLC found.

0. Start: 无已配对设备: 无配对码，无事件流，未订阅通知，已推送0次
1. 电脑生成配对码. Now: 无已配对设备: 配对码有效，无事件流，未订阅通知，已推送0次
2. 手机打开配对链接. Now: 手机已配对: 配对码已用，无事件流，未订阅通知，已推送0次
3. 手机打开事件流. Now: 手机已配对: 配对码已用，事件流在线，未订阅通知，已推送0次
4. 手机开启通知. Now: 手机已配对: 配对码已用，事件流在线，已订阅通知，已推送0次
5. 手机在前台查看会话. Now: 手机已配对: 配对码已用，事件流在线，已订阅通知，正在前台查看，已推送0次
6. 会话进入等待审批. Now: 手机已配对: 配对码已用，事件流在线，已订阅通知，正在前台查看，30秒内已通知，已推送1次
