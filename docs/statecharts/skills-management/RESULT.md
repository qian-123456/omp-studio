# Skills 管理：现状状态图与交互建议

## 范围与结论

本次是分析与设计建议，不是应用修复。应用源码、真实技能文件和用户配置均未修改。

源码基线：`c180b3bbd63862788e6bf6d1ba2b2cfb04ac8421`；实际读取的技能 store Git blob：`9ccd5db99ff2af91a3a96b1a95fc2259cccd7b0c`。用户截图用于理解现有操作体验，不是删除失败的运行证据。

用户框选的行显示“来源已关闭”，安装位置仍是 `~/.claude/skills`。这表示文件仍被发现，但该来源不参与新会话的自动加载，不表示已经删除。截图另有“4 处副本”“3 处副本”的技能；副本问题和来源关闭是两个独立维度。

主要结论：

- **信息组织问题**：列表按名称合并技能，却只展示一个优先位置；移除操作也只处理这个位置。移除后其他位置接替，用户会觉得没有删干净。现有确认框确有剩余副本警告，不能说完全没有提示。
- **操作含义问题**：来源关闭会锁住单项开关，但文件仍能查看、移除；选中了会话时还允许临时使用。统一标成“启用”且弱化整行，容易让用户把不同操作误读为全部不可用。整行弱化条件见 `src/features/skills/SkillsPage.tsx:1323-1327`；没有选中会话时，使用按钮另行置灰，见同文件 `266-267,1427`。
- **已回放的前端缺陷**：移到废纸篓成功后马上提示成功；随后目录重载失败时，旧的已移除位置仍在列表里，操作也已解除忙碌状态。页面同时展示错误提示和旧表格。
- **恢复边界**：移除符号链接只移走链接，不移走真实目标；这是保护共享文件的行为，不应改成自动追踪删除目标。

## 不应混报为缺陷的行为

1. **移除一处后同名技能仍在**：扫描顺序确定胜出位置；后续来源只增加副本计数，路径信息不保留在列表响应里。移走当前目录后，其他位置成为新胜出项。`src-tauri/src/skills/commands.rs:328-426,536-630`；确认警告在 `SkillsPage.tsx:203-206`。前端接收另一副本的行为已回放；实际后端扫描规则来自源码阅读。
2. **来源关闭不删除文件**：启用计算检查来源配置，目录扫描独立进行。`src/lib/skillEnablement.ts:189-209`、`src-tauri/src/skills/commands.rs:536-630`。
3. **来源关闭后仍可移除**：行删除按钮只因正在移除同一目录而禁用。`SkillsPage.tsx:1450-1454`；公开前端移除入口已回放。
4. **停用后仍可临时使用**：选中了会话、且不缺技能文件时，会写入显式的“本次临时使用”读取指令；不会重新打开自动加载。`SkillsPage.tsx:236-264,675,1427`。这是源码阅读结论，未做输入框运行回放。
5. **符号链接目标仍在磁盘上**：删除校验保留链接路径，系统废纸篓处理链接自身。`src-tauri/src/skills/commands.rs:668-745`；现有测试位置 `src-tauri/src/skills/tests.rs:615-650`，本次没有运行该后端测试。

## 优化建议与优先级

### P0：修正移除结果，不让用户猜

- 操作分成“正在移除”“文件已移除，正在核对列表”“完成 / 仍有副本 / 核对失败”。不要用一个泛化成功提示代表整个流程完成。
- 已确认移走的旧位置立即不可再次操作；扫描失败时保留明确的“文件已移除，列表刷新失败”状态和“重新核对”入口，而不是把旧目录恢复成可操作安装位置。
- 部分成功要逐个列出成功、失败和剩余位置；不能把部分成功写成全部完成。
- 只在当前扫描范围内报告“已无副本”，不要声称整台电脑或外部安装器永久不会再出现它。

刷新恢复对照模型只证明“隔离本次被移除的逻辑行可消除旧目录问题”；它并不证明磁盘已无其他副本。列表待核对时不能把隐藏该行解释为全部卸载。完整交互建议图进一步把这些反馈分开。

### P1：一个技能一行，所有安装位置可展开

- 行内显示“发现 4 个位置”，点击展开各位置；每项给出全局/项目范围、完整路径、当前胜出/备用、普通目录/链接，以及来源是否参与加载。
- 默认提供“仅移除此位置”；另提供明确的“移除所有已发现位置”，确认前列出确切目标与影响范围。不得自动跟随链接删除共享目标。
- 现有后端响应只有胜出位置和计数；要实现真正的全位置管理，必须先扩充目录响应，再设计选择和逐项结果。只改按钮文案做不到完整删除。
- 如果技能由外部工具安装、受外部管理或为共享链接，说明管理来源，并给出相应入口；未识别管理归属时不要假装可以阻止再次安装。

### P1：拆开文件存在、自动加载、本次使用

- “启用”改为“新会话自动加载”；已启动会话是否生效另行说明，不能承诺会同步撤回已有上下文。
- 来源关闭时，常驻显示原因和“查看来源设置”，说明开启会影响同来源的其他技能；不要让单项开关偷偷改整个来源。
- “使用”区分“用于当前会话”和“仅本次使用”。没选会话时给出“先选择会话”，不要只留下灰色播放图标。
- 只弱化自动加载状态，不要把名称、路径、文件夹与删除操作整行淡化成无法点击的外观。

### P2：列表围绕管理任务组织

- 默认突出技能名称、加载状态、安装位置数和可发现的“更多”操作。触发次数、最近使用等保留为可排序的辅助信息，而不是与管理状态争夺主要视觉层级。
- 停用原因、完整路径、删除范围不只依赖悬停；支持键盘与触屏。
- 保留已有布局和组件体系，先修语义与状态反馈，不做整页重设计。

## 重现命令

在仓库根目录运行：

```sh
JAVA=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home/bin/java \
TLA2TOOLS="$HOME/.cache/statechart/tla2tools.jar" \
node docs/statecharts/skills-management/regenerate.mjs
```

其他机器指定自己的 `JAVA`、`TLA2TOOLS`；可用 `STATECHART` 指定技能脚本路径。默认使用 `$HOME/.agents/skills/statechart/scripts/statechart.mjs` 和仓库已安装的 Vitest。所用 TLC jar SHA-256：`936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88`。

脚本把模型复制到新的外部临时目录，执行以下检查，再发布结果到本目录 `out/`：

```sh
node "$STATECHART" from-spec SkillsCurrent.tla --expect-broken NoSettledStaleRow --png --out current
node "$STATECHART" from-spec SkillsCurrent.tla --fixed SkillsProposed.tla --label 建议方案尚未实现 --expect-broken NoSettledStaleRow --cover --png --out comparison
node "$STATECHART" from-spec ProposedDesign.tla --png --out proposal
```

完整带标题的命令在 `regenerate.mjs`，TLC 的配置与原始输出在各 `out/*/tlc/`，公开入口回放的精确命令和退出状态在 `out/replay/execution.json`。

## 模型边界与尚未完成

- 当前模型只覆盖一个技能、至多两个来源、按顺序的移除和目录刷新。磁盘目录集合是文件存在性的有限抽象，目录集合到胜出行和副本计数的映射来自扫描代码。
- 未建模来源配置写入、外部重新安装、任意数量副本、符号链接共享身份、权限变化、磁盘持久性、跨窗口并发、项目切换、后台刷新竞态、进程退出和已有会话上下文。不得据此声称这些场景安全。
- 刷新恢复模型是建议，并没有新增产品实现。完整建议模型的条件是设计条件，不伪装成现有代码守卫。
- 未运行真实 Rust 删除命令、真实废纸篓操作、后端扫描测试或原生窗口验收；不得据此声称用户具体那次删除已重现。
- 未运行全量测试、应用构建、lint 或格式化，因为只新增独立分析文档和外置回放资料。
- 应用接口契约未改；Git 提交仅包含本目录。未推送、未建 PR；未同步 Coding Wiki，因为本次是项目局部分析，不是通用规则变更。
